# Ordis v1.0 测试报告（公开版）

> 本报告只保留可公开的测试结论，不包含测试主机地址、访问凭据、模型密钥或生产配置。

## 1. 测试范围

- SQLite 持久化、旧 JSON 数据迁移和审计记录。
- 传统业务检测、修复效果回检和命令失败识别。
- Kubernetes 只读检测与权限边界。
- AI 诊断 JSON 解析、指纹去重和自动修复/邮件建议分流。
- 技能查重、审核、合并和规则同步。
- server/agent 鉴权、订单回执和重试幂等。

## 2. 自动化回归

测试使用 mock 隔离模型和外部服务，避免真实 API 调用：

```bash
python3 -m unittest discover -s ordis -p 'test*.py'
python3 -m compileall -q ordis
git diff --check
```

覆盖内容包括 AI 诊断、对抗性输入、技能链、权限分级、传统检测、健康修复、Kubernetes 检测、CLI 和配置向导。

## 3. 关键验证结论

### SQLite 与迁移

- 案例、草稿、技能、事件和审计数据可写入 SQLite。
- 数据路径遵从 `ORDIS_HOME`。
- 旧 JSON 文件按文件独立事务迁移。
- 迁移成功后保留 `.migrated` 备份，失败时回滚并保留原文件。

### 检测与修复

- `ordis check` 和 `ordis k8s check` 默认只读。
- systemd、Docker、业务端点和 Kubernetes Finding 使用稳定指纹。
- 修复命令不能仅凭退出码判定成功，必须通过端口、服务状态或资源状态回检。
- 未纳管或不在白名单中的服务会跳过写操作。

### AI 接管

- AI 诊断在后台异步执行，不阻塞正常巡检循环。
- 相同故障指纹具有去重和并发保护。
- `auto` 模式执行前经过权限检查，成功后必须回检。
- `email` 模式只发送管理员建议，不执行 AI 命令。
- 诊断命令不会被误收录为修复技能。

### 技能审核

- AI 生成的技能先进入待审核状态。
- 相同指纹或规范化命令会触发查重。
- 重复草稿需要人工合并，确认后才会更新规则。
- 缺少效果回检条件的候选技能不会进入可执行技能库。

### 集群

- 管理接口与节点接口使用不同 token 权限。
- 未授权或错误 token 被拒绝。
- 订单状态支持 `pending`、`sent`、`done`、`failed` 和 `timeout`。
- 超时订单有限次重试，agent 按订单 ID 幂等处理，避免重复修复。

## 4. 已知限制

- 当前 Kubernetes 检测定位为基础兼容能力，不替代 Prometheus、Alertmanager 等生产监控体系。
- 自动修复依赖明确的白名单、权限配置和效果回检。
- 大规模集群、长期压力、升级回滚和高可用部署仍需继续验证。
- 生产使用前应补充更完整的密钥管理、审计告警、备份恢复和发布流程。
